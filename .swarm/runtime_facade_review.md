## Important

1. **Capabilities claim FK and single/paired IK operations that the facade does not provide.** `capabilities_for()` unconditionally sets `OA_RUNTIME_CAP_MODEL_FK`, `OA_RUNTIME_CAP_SINGLE_XYZ_IK`, and `OA_RUNTIME_CAP_PAIRED_XYZ_IK` for virtual, SocketCAN-query, and offline runtimes (`runtime/src/runtime.cpp:90-105`). The complete public function list (`runtime/include/openarm_runtime.h:432-534`) has no runtime FK function, no single-arm XYZ solver, no atomic paired XYZ solver, and no model-identity query. `oa_runtime_get_kinematics` is measured-state-only and unsupported for query/offline runtimes; paired TCP planning requires an armed virtual controller and is not a query-only IK operation. The coordinate ABI also omits the required model/data/URDF digest, exact named TCP identity/revision, and collision policy (`openarm_runtime.h:314-395`). This makes capability discovery materially false and leaves callers unable to bind coordinates to the exact model/TCP artifact.

2. **The advertised runtime monotonic clock is invalid for SocketCAN-query and offline runtimes.** `timeline_ns` starts at zero and is initialized/advanced only inside the virtual-backend branch (`runtime/src/runtime_internal.hpp:92-108`, `runtime/src/runtime.cpp:213-268`), while `oa_runtime_now_monotonic_ns` always returns that field (`runtime.cpp:307-316`). Physical inventory uses the host steady clock for query deadlines and returned send/dequeue timestamps (`runtime/src/inventory.cpp:253-285`) but labels evidence with the same `OA_RUNTIME_CLOCK_MONOTONIC`. Thus a query runtime reports `now == 0` while returning nonzero evidence timestamps in the allegedly same domain, defeating freshness/deadline composition. Virtual inventory also fabricates both query and response timestamps as `1` (`inventory.cpp:42-43`).

3. **Multiple outstanding plans can freeze an executing command indefinitely.** Every successful plan increments `paused_plans`; the cadence remains stopped while the count is nonzero (`runtime/src/runtime.cpp:239-247, 429-432, 497-500`). Execute decrements only the executed plan's contribution (`runtime.cpp:596-603`). A focused Release consumer created two valid joint plans from the same measured sequence, executed the first, and waited 100 ms: `timeline_before=14166461267979`, `timeline_after=14166461267979`, `frozen=1`. Destroying the second plan immediately resumed the timeline. Since expiry and heartbeat are also evaluated on the frozen timeline, the command neither advances nor times out. The facade needs one outstanding-plan authority or must resume cadence independently of unrelated plans.

4. **Supervised calibration does not bind interlocks, posture, or evidence to runtime-owned state, and its session state is not concurrently safe.** `oa_runtime_calibration_recipe_step` copies the caller's entire input and replaces only `now_ns` and the target joint encoder (`runtime/src/calibration.cpp:209-225`). Caller assertions for `estop_clear`, `deadman_held`, `operator_ready`, posture mask/vector, action completion, evidence revision, and fixture revision pass through unchanged even though the runtime owns interlock state and a coherent seven-joint snapshot. An advisory action can therefore be produced from claims that contradict runtime state. In addition, `CalibrationData::finished` is a plain `bool` (`runtime_internal.hpp:120-128`) read without the runtime mutex (`calibration.cpp:15, 213, 232, 245`) and written under the mutex (`calibration.cpp:61-66, 250-253`), so overlapping step/sample/commit/abort calls have a C++ data race and can race lease release/publication. Physical actuation remains unavailable, which limits impact, but calibration evidence and transactional authority are not sound.

5. **Persistence provides an unkeyed checksum and public magic value, not authenticated authority or provenance, and its failure contract is incomplete.** `OA_RUNTIME_PERSISTENCE_AUTHORIZED` is a public constant (`openarm_runtime.h:430`) checked by equality (`runtime/src/persistence.cpp:135-140`); any caller can pass it. The in-file SHA-256 is unkeyed, so anyone able to modify the artifact can modify fields and recompute the digest. There is no signature/MAC, accepted-artifact record, monotonic revision store, retained prior revision, or reload-after-save verification. Also, if rename succeeds and directory `fsync` fails, save returns `OA_RUNTIME_EIO` after the new target has already replaced the old one (`persistence.cpp:178-184`), contrary to a failure-leaves-old-artifact-intact contract. The format is deterministic and corruption-detecting, but not authenticated persistence.

6. **Allocation-failure containment is incomplete at the C boundary and in physical inventory cleanup.** `oa_runtime_manifest_preview_file` performs allocation-heavy path parsing and manifest parsing without an outer `try/catch` (`runtime/src/persistence.cpp:114-133`), so `std::bad_alloc` can escape an `extern "C"` API instead of returning `OA_RUNTIME_ENOMEM`. In physical inventory, a raw transport is opened at `inventory.cpp:217-221`, cleanup occurs only at `296-297`, and later vector/string/hash allocations can throw (for example `result->motors.push_back` at `294`); the outer catch at `329-330` returns ENOMEM without closing/destroying that transport. No production allocation-failure injection exists, so the normal-path sanitizer suite cannot cover these paths.

7. **Event evidence is invented or omitted rather than exact.** `oa_runtime_event` exposes per-arm feedback sequences and a measurement timestamp (`openarm_runtime.h:407-428`), but event translation never assigns `measurement_runtime_monotonic_ns` and copies the lower controller's single minimum/global sequence into both arm slots (`runtime/src/runtime.cpp:660-680`; lower source derives that scalar with `min(left,right)` in `control/src/control_core.cpp:1217-1224`). A zero measurement timestamp and duplicated scalar are not exact per-arm evidence. The event must either snapshot exact per-arm values atomically or mark them unknown/absent.

8. **Status/detail translation loses authoritative causes.** `map_control` omits `OA_CONTROL_EUNREACHABLE`, so a genuine paired-IK unreachable result falls through to `OA_RUNTIME_EINVAL` (`runtime/src/runtime.cpp:18-34`). Most wrappers return mapped lower errors without updating `last_error`; only snapshot failure and a narrow worker-error path call/set the detailed facility/lower code (`runtime.cpp:254-262, 330-344`). Consequently `oa_runtime_get_last_error` can remain `OK` or stale after plan, execute, interlock, calibration, inventory-open, heartbeat, stop, or disarm failures, defeating the advertised `{facility, lower_code}` authority.

## Minor

1. **ABI errors and semantic input errors are conflated.** Invalid backend/cycle/boolean options return `OA_RUNTIME_EABI` (`runtime/src/runtime.cpp:172-199`), as do wrong clock/unit/frame/orientation values on plan requests (`runtime.cpp:421-424, 486-491`), while equivalent clock errors in heartbeat/disarm return `OA_RUNTIME_EINVAL`. `oa_runtime_get_kinematics` also returns unsupported for an out-of-range side when a controller exists because side validation is combined with backend availability. This makes recovery and diagnostics inconsistent even where the ABI version/size is valid.

2. **The repository build script now requires `cmake --fresh` despite component minimum versions of 3.16.** `scripts/build_native.sh:139` applies `--fresh` to every component; that command-line option was added after CMake 3.16. The current review host supports it and the integration is otherwise logically ordered, but the documented/configured minimum toolchain is no longer sufficient.
